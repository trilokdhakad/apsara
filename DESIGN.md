# Design Principles

## Overall direction

The website should feel like a serious technology company introducing a large product thesis.

Reference direction:

- premium technology startup
- editorial product design
- Linear / Vercel / Ramp-style restraint
- strong typography
- deliberate whitespace
- sophisticated product UI

It must NOT look like:

- an education coaching website
- an ed-tech template
- a generic SaaS template
- an AI landing-page template
- a marketing agency website

The visitor should think:

"This is a technology company building something substantial."

## Visual hierarchy

Priority order:

1. Company/product idea
2. Real counselling demonstration
3. Data and intelligence
4. Broader vision
5. Call to action

The real Indian case study is the primary visual proof after the hero.

## Color and section differentiation

Do not make the entire page one continuous white canvas.

Sections must have visible visual relationships and transitions.

Use a restrained tonal system rather than excessive decoration.

Possible section treatments:

- warm off-white
- pure white
- very light neutral gray
- subtly tinted neutral section
- near-black / dark section for major vision or intelligence moments
- thin rules and borders

Do not introduce multiple accent colors.

A section may use a distinct background treatment when it improves hierarchy.

Background changes should feel intentional, not decorative.

Do not use a different bright background for every section.

The page should have visual rhythm:
light → white → darker product area → light → dark/strong vision → light CTA

The precise sequence may change based on the final layout.

## Color restraint

- One primary accent color.
- Avoid rainbow palettes.
- Avoid neon accents.
- Avoid glowing surfaces.
- Avoid excessive gradients.
- Do not use color simply to fill empty space.

Color should communicate hierarchy, state, or meaning.

## Typography

Typography is a major part of the visual identity.

Prefer:

- Geist or another installed modern grotesk
- large editorial headlines
- tight headline tracking
- restrained body typography
- clear hierarchy

Avoid excessive font sizes.

Avoid using bold weight everywhere.

Headlines should feel confident rather than promotional.

## Layout

- Prefer large open areas over dense sections.
- Use a constrained content width.
- Use asymmetry where it improves composition.
- Do not center everything by default.
- Avoid filling the viewport merely because space is available.
- Use generous vertical rhythm.
- Use visual contrast between sections.
- Allow important sections to breathe.
- Use alignment to create structure.

Not every section should have the same centered heading + three cards pattern.

## Section composition

Each major section should have a distinct visual role.

Examples:

Hero:
large typography + minimal navigation

Case study:
large product interface + supporting explanation

Round evolution:
interactive timeline/data transition

Data/intelligence:
strong typographic treatment + structured data signals

International:
different but related case treatment

Vision:
large, sparse, high-contrast statement

Waitlist:
simple, quiet conversion point

Avoid repeating the same card layout throughout the page.

## Product UI

The counselling interface should feel like a real product.

It should:

- use realistic information density
- have clear hierarchy
- use restrained borders
- avoid dashboard clutter
- avoid fake charts that communicate nothing
- avoid decorative statistics
- prioritize readable data over visual effects
- make changes between rounds visually obvious
- communicate uncertainty honestly

The product preview is more important than decorative marketing graphics.

## Data visualization

Data should look meaningful, not ornamental.

Prefer:

- ranked lists
- comparison rows
- movement indicators
- timeline transitions
- compact metrics
- before/after changes
- clearly-labelled signals

Avoid:

- meaningless circular charts
- giant percentage circles
- decorative graphs
- fake stock-style charts
- arbitrary animation

Every visualized number must have a reason to exist.

## Animation

Use animation selectively.

Good:

- round transitions
- subtle entrance animation
- state changes
- number transitions
- row movement
- hover/focus feedback

Bad:

- constant floating elements
- particles
- animated gradients
- excessive parallax
- decorative bouncing
- scroll-jacking
- animations that slow comprehension

Motion should communicate change.

The round-to-round strategy transition is the primary animation opportunity.

## Image policy

Do not use stock student photos.

Do not use decorative AI-generated images as filler.

If imagery is introduced later, it must support the product thesis.

The product interface and typography should carry the visual identity.

## Copy presentation

Copy should be concise.

Avoid walls of text.

Use short paragraphs and strong statements.

Do not put every product detail on the homepage.

The page should communicate:
problem → thesis → proof → intelligence → vision → action.

## Responsive behavior

Desktop is the primary showcase.

Mobile must remain excellent rather than being a compressed desktop layout.

Important product information must remain readable without horizontal scrolling.

Interactive case-study elements must have a deliberate mobile representation.

Do not simply shrink large desktop tables.

## Anti-template rule

Do not use the same visual pattern for every section.

Avoid:

Section heading
↓
Three cards
↓
Section heading
↓
Three cards
↓
CTA

The page must have composition and pacing.

## Anti-AI-slop rule

No:

- purple AI glow
- floating glass panels everywhere
- excessive rounded rectangles
- gradient text by default
- fake badges
- meaningless "powered by AI" labels
- fake logos
- fake customer testimonials
- fake usage counts
- decorative robot imagery
- excessive iconography
- generic SaaS illustrations

The website should look designed, not generated.

## Brand feeling

Apsara should feel:

- intelligent
- calm
- ambitious
- technical
- trustworthy
- global
- understated

Indian identity should be subtle.

Do not rely on stereotypical Indian visual motifs to communicate identity.

## Product proof

Real data should be the strongest design asset.

Whenever possible:

real case
→ real structure
→ real changes
→ real explanation

is preferable to:

illustration
→ marketing claim
→ generic diagram.
